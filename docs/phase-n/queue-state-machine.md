# Queue state machine
WAITING → OFFERED: serialized worker, oldest eligible admission sequence, genuine ready listener and protected capacity. OFFERED → TRANSFERRED: owning member confirms the exact immutable allocation before both deadlines; insert one bound Phase I request and mark transferred in the same transaction. Request acceptance/activation occurs later through I.

WAITING/OFFERED → CANCELLED: member explicitly leaves or declines. → EXPIRED: parent twenty-minute deadline or proposal deadline. → SERVICE_UNAVAILABLE: feature/staffing loss, conflicting member commitment, or readiness loss after an offer. A temporarily unready listener between sessions does not renew or silently cancel an existing WAITING entry while an independently staffed qualified window remains; the UI clearly shows the lack of readiness and no new admission is allowed from that window alone. → SAFETY_TERMINATED: current eligibility, qualification or block failure. Terminal rows cannot return to active states under the DB transition trigger.

The queue stores one immutable allocation per attempt. A timeout is terminal; it never silently returns the member to WAITING. A restarted worker reads the same allocation/deadline and cannot duplicate transfer. Parent admission, deadline, ordinal, language and notice choice are immutable. Database revisions plus the admission ordinal prevent a delayed client response from replacing newer or terminal state. Foreground generation checks discard late responses after navigation, backgrounding, hidden privacy state or unmount.

A valid TRANSFERRED row is historical linkage; the child I status is returned separately so a completed previous attempt does not prevent an explicitly chosen new attempt. No queue read itself creates an admission or live request.
