## Replay boundary

Additive V88 stores immutable preparation, subject-purpose restrictions, stopped services, independent review and invalidation. No accounts, approvals or service activation are seeded. Normal mode does not add runtime queries. For **every restored deployment**, supply a fresh externally held `GREENOCEAN_RESTORE_EPOCH`, exact source commit and `GREENOCEAN_RESTORE_MANIFEST_SHA256`. Do not copy a previous epoch from the backup. Deployment/key custody must keep these values outside that backup.

Build the authoritative manifest from current rights/deletion/revocation records outside the old snapshot. `RecoveryReplay.manifestDigest` defines GOREPLAY1 canonicalization: exact40-character source hash, sorted distinct `subjectUUID:DOMAIN` lines, sorted stopped service names, SHA-256 over UTF-8 with LF. The server recomputes the digest from the submitted payload; merely repeating an approved digest cannot authorize substituted restrictions. Maximum5000 subjects and5 service classes. An absent user is a reconciliation issue, not an invented successful replay.

Before independent review, data APIs fail closed; authentication, crisis resources, health and purpose-protected recovery routes remain available. Two distinct current TRUST_ACCOUNT operators with recent strong authentication prepare/review within one hour. All-purpose restricted subjects have restored sessions revoked; listed purpose restrictions remain checked after general recovery. Pauses remain separate from runtime service authorization. Removing an operator's purpose authority or restricting their account permanently invalidates that epoch, even if the role/account is later restored. Explicit invalidation also closes data access again. A new externally controlled epoch is needed to replace a revoked approval.

The EN/FA staff review shows the exact source/hash, subject-purpose list and stopped services before independent attestation; it does not grant the source clinical/financial authority. This is a conservative denial boundary, **not erasure execution or automatic reconstruction of an external rights ledger**. Unlisted withdrawals/deletions cannot be inferred from an old snapshot. Real recovery remains blocked until the authoritative ledger, object inventory, key custody and reviewer coverage are established and an end-to-end rehearsal passes.
