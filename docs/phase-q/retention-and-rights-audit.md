# Rights, retention and restore audit

Q2 extends the existing AccountService archive with `trustAndSecurity`: only the subject's coordination receipts and own exceptional request metadata. It excludes source narratives, source subject identities, reviewer identities and session credentials. Clinical content remains behind the existing category-specific authenticated rights process rather than being copied into a general social archive.

AccountRepository revokes the subject's trust coverage and social exceptional approvals/requests before erasing source assessments. V86 cascades assessment-linked attribution requests, avoiding a foreign-key erasure blocker and preventing later reuse. Clinical and financial obligations continue to require the existing source review; Q2 does not manufacture consent, erase legally held records automatically or declare an unfinished file erasure complete. Existing account_file_erasures tracks external document work independently of the database deletion transaction.

V86 is additive and transactional: PhaseQ2MigrationTest injects a conflicting relation after populated V85, checks rollback leaves the old schema/source data intact, retries successfully and verifies validation with no fabricated grants. Historical exceptional grants are unbound and denied. Immutable scope and irreversible revocation triggers are covered by Q2 tests.

Session bindings are immutable opaque historical approval references, not foreign keys that force sessions to survive erasure. Every use still requires a matching current live session. Erasure clears Q1 nullable session references on revoked coverage and invalidates pending approval expiry before deleting sessions. Q2 fixtures exercise staff erasure with independently approved evidence, source-author erasure cascading evidence requests, and acknowledged operator erasure removing usable coverage. These additions require final validation in test-evidence.md; do not infer a passed result from the fixture's presence.

Limits: database migration, local cryptographic rotation tests and a synthetic backup are not evidence of production retention approval, object-store destruction, removal from every provider, real key rotation or backup rights replay. A restored backup can contain old rights state; external withdrawal/erasure/hold reconciliation must run before admissions are reopened. Q4 must exercise an isolated restore and replay with measured results. No production restore, arbitrary retention duration, actual legal review or data-controller approval is recorded here. These remain release blockers until evidence exists.
