# Pilot stop criteria and response

Immediately stop affected new admissions for confirmed confidentiality breach, unauthorized clinical activation, payment ledger inconsistency, uncontrolled duplicate booking/rewards, critical unresolved access defect, loss of mandatory coverage, unrecoverable object/database corruption or uncontrolled major outage. Lower-severity warning thresholds require an actual approved infrastructure budget; local Q4 measurements are not contractual SLAs.

Duty incident owner invokes scoped Q3 pause, ensures real escalation acknowledgement and safe current-session/care handling, preserves evidence and reconciles obligations. Platform staff revokes the assessment; new requests must fail even if a client retains old parameters/token. Do not equate an HTTP callback, queued alert or refund obligation with confirmed provider delivery/payment/refund.

Restart requires current independent investigation/recovery review, exact-source regression, restored coverage/providers, approved communications and explicit owner scope. Never silently re-enable a revoked assessment; create a new independently reviewed assessment. No deployment, real outreach, refund transfer, recruitment or production activation is performed by this implementation.
