# Trust coordination

Q1 extends existing Reports, support assistance, P4 professional cases and P5 operational incidents with one purpose-isolated metadata coordinator. V84 stores opaque source references, fixed category/severity/state, assignment, bounded approval and structured event codes. It never copies source narratives, contact details, anonymous attribution, journal entries, clinical notes or listener transcripts. UI queue/detail are explicit projections. Source evidence is opened only through existing L/M/I/N/P authorized workflows; a trust role never grants those permissions.

TRUST_SOCIAL (including GROUP), TRUST_LISTENER, TRUST_CLINIC, TRUST_FINANCE, TRUST_ACCOUNT, TRUST_EDUCATION and TRUST_PLATFORM are explicit current database roles. ADMIN/MODERATOR have no implicit trust scope. A current active verified account, valid current session and recent strong MFA are required by the service layer. New roles join the existing privileged-session policy. Role seeding creates no operator or legal approval. Processing is default-off via GREENOCEAN_TRUST_ENABLED.

TrustSources contains fixed allowlisted adapters. Reports infer group/listener/account context from existing references, never from guessed prose. Clinical incident/category and reputation adapters use minimal metadata without decryption. Existing support requests can be manually classified into ACCOUNT/EDUCATION/PLATFORM coordination, with the domain retained and audited. Categories include post/comment, harassment/privacy, group/listener conduct, professional/financial, account, education and platform. Source workflows retain substantive decisions, evidence grants and appeals; coordination does not silently enforce sanctions.

Own /account/safety-cases contains minimal receipts linked only to the authenticated original submitter. Staff history contains states and fixed reasons without subject identities. All authenticated responses inherit no-store. Public availability returns one boolean and explicit false emergency/continuous-monitoring claims, never staff identities. Resources reuse the existing urgent-help workflow; Q1 invents no helpline or verification.
