## B. Policy and standards

The authoritative [authentication/session policy](../security/authentication-session-policy.md) documents each EF-P policy's risk, actual standard/version, product decision, enforcement, behavior, tests and rollout exception. [Verified control mapping](../security/control-coverage.md) and [threat model](../security/phase-ef-threat-model.md) provide the scoped standards review. NIST SP800-63B-4, the official tagged ASVS5.0.0 CSV, MASVS2.1.0 and the five relevant live OWASP cheat sheets were reread. SHALL, SHOULD and MAY are distinct from product choices. This is no certification, complete ASVS L1/L2 assessment, or production AAL2 service claim.

Approved product defaults: password15–128 Unicode code points; access JWT15minutes; ordinary web overall24hours/idle30minutes; ordinary mobile30days/24hours; privileged12hours/30minutes; local native background privacy lock5minutes; sensitive proof freshness10minutes. The numeric session values are GreenOcean risk choices, not universal NIST rules. Separate limited PENDING scope is1hour/15minutes. Silent refresh/polling never restarts meaningful activity or original overall lifetime. Password change/reset revoke every session; suspension/deletion deny existing access. Password or key confirmation is sensitive-operation step-up, not a renewal of original session lifetime.

E12 consumer passkeys and E13 optional member MFA are explicitly deferred. Staff WebAuthn is implemented/tested with genuine browser-generated signatures, but production staffing/origin/hardware/recovery approval remains blocked; administration stays disabled. Email verification and local native privacy are not MFA.

## C. Code and database changes

The authoritative [file-by-file diff inventory](file-map.json) lists every changed path against Phase D. Meaningful groups:

- Backend authentication reuses AuthenticationService, compatible PBKDF2/legacy BCrypt, existing C normalization, durable limits, bounded password work, rotating verifier-only refresh families and live JWT/session/role authorization. SessionPolicy/RecentAuthentication enforce absolute/idle/freshness bounds without client timestamps.
- Password step-up now binds bearer, account/session and current refresh, verifies the real password, increments V39 token_version and rotates refresh atomically. Prior bearer credentials immediately fail. Browser proof has its own Origin/header-checked HttpOnly-cookie endpoint; native proof returns a fresh secure token pair. Both keep original lifetime bounds and fail closed on wrong-owner refresh or concurrent replay.
- Yubico WebAuthn registration/assertion verifies challenge, RP/origin, signature and user verification. Ceremonies are owner/session-bound and one-use; independent first-enrollment permits prevent password-only staff takeover; factor removal requires strong proof/backup and revokes sessions. Recovery never invents staff assurance.
- Frontend reuses Profile → Account & Security and existing login/public assistance routes. Registration now uses one shared visibility controller with preserved labels instead of a legacy duplicate. Shared masked fields provide autofill/paste/visibility and LTR secrets under EN/FA. Password change, confirmed individual/all-device removal, safe labels/times, security events, genuine key controls and recoverable errors use actual services.
- Browser access remains memory-only; refresh stays in narrow host-only HttpOnly/Strict cookies, Secure on HTTPS. Origin-scoped Web Locks coordinate cookie mutations. Pending offline logout blocks restore and reconciles before a fresh sign-in. New cross-tab login removes completed local blocking state without revoking the newly established cookie again. Merely reconnecting an active session no longer claims logout.
- Private provider keys/epochs reject A's late data after logout or B login. Native proof/refresh mutations and SecureStore credential pair I/O are serialized; late requests use the current verifier and old account generations cannot store credentials or issue follow-up sensitive actions. Native content is hidden on inactivity with OS capture/app-switcher protection and a5minute server-login fallback; unencrypted draft persistence is not introduced. Retention excludes legal/moderation evidence. Notification coalescing and provider status limits are documented.
- Database migrations: V37 bounded original session lifetimes/credential/ceremony tables; V38 independent enrollment permits; V39 token assurance version. ## F. Demonstrated security properties

Real authorization evidence shows that signature/issuer/claims/session/version checks reject forged, expired, revoked and stale-role tokens; pending refresh never becomes social activation. Rotating refresh cannot extend original lifetime. Ordinary password proof does not set staff MFA. Independent enrollment, RP/origin/UV/signature, one-use challenges and pre-proof invalidation protect the actual staff boundary. Owner-scoped session/recovery operations cannot alter another account. Parallel consume/rotation and logout/reset/revoke races have persisted safe outcomes. Generic errors, early/body/account/source limits, safe fixed event shapes and private-cache epoch tests were exercised. These are scoped demonstrated properties, not a proof of absolute security, constant-time networking or certification.

## G. Remaining dependencies and residual risks

- E06: real mail gateway/sender/DNS, approved HTTPS recovery destination, reviewed templates and authorized staging inbox/callback delivery exercise remain external. Controlled QA mail confirms code behavior, not production delivery.
- E14: production staff access remains disabled. RP/origin approval, physical/backup factors, independently controlled enrollment permits, approved staff roster, dual-reviewed lost-factor recovery and deployment approval are required. No password/email fallback or self-granted role is introduced.
- Native UI/storage/lock/autofill/capture/share/deep-link/backup and assistive-technology runtime tests are unexecuted. Source/export checks alone cannot clear them; see native-validation.md. Compromised devices can defeat OS controls.
- External immutable collection, alert routing/threshold tuning and safe incident notification remain unexercised. Event caps and mail coalescing mean bounded/sampled history, not complete forensic or per-event delivery evidence.
- Production corpus/TLS/ingress/exact origins/static-host CSP/no-referrer/no-store/log redaction/backup/key management remain operator checks. Cookie theft/XSS can still misuse a legitimate origin; HttpOnly is not complete XSS protection.
- Strict refresh replay may force login after a lost rotation response; do not add a grace bypass that accepts a stolen retired token. Web Locks require a supported secure browser. Unknown old mobile sessions use conservative legacy bounds, communicated before release. Token-response changes require coordinated clients/backend.
- In-flight operations already authorized before revocation cannot be recalled; subsequent authorization decisions reject the session. Unsaved private drafts are deliberately discarded on logout/expiry/long background instead of copied to unencrypted persistent storage. User-saved exports and another app's shared copy are outside recall; crash-time native cache behavior still requires device/operations review.
- Standards coverage is targeted; full ASVS L1/L2 and AAL2 certification are not asserted. E12/E13 remain approved deferred consumer scope.
