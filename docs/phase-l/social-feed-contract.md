# Social feeds and consensual connections

All discovery is authenticated, service-eligible and chronological (created_at DESC,id DESC). /posts/discovery accepts DISCOVER, FOLLOWING or SAVED, optional category UUID and an opaque-to-UI timestamp/UUID cursor; size1–100. Cursor is a boundary, never authorization. Every page reuses can_read_social_post, current blocks/membership/relationships, content status/deletion and existing warning/muted-term controls. Newer inserts cannot shift cursor pages. Refresh intentionally returns to the first page; no engagement or sensitive-topic ranking.

FOLLOWING additionally requires a current follow and excludes ALL anonymous posts. Knowing a hidden author's relationship must not select anonymous content into this named feed. DISCOVER and SAVED may include anonymous content only under its original authorized audience. Bookmarks never grant access; removing a stale bookmark is owner-scoped and succeeds without revealing inaccessible content. Saves remain private and do not notify authors. No public popularity metrics added.

UI tabs request distinct server queries, have loading/error/empty states and explicit load-more. In-memory post cards adopt revalidated server props; they do not retain an old narrative after a newer permitted response. Active social feeds revalidate every15seconds and clear on blur/background/auth privacy cleanup. Revocation on another device cannot be known instantaneously without an event channel; direct reads and each mutation always recheck server authorization, and no persistent narrative cache is added. Previously viewed/copied content cannot be remotely erased.

Replies retain the same-post visible parent constraint, at most8 server levels, and at most two mobile indentation levels with explicit context. Deleting a parent does not display its old body. Comments use the L1 safety gate, anonymous DTO redaction and owner-scoped deletion. New comments by an anonymous post's owner are forced anonymous, with no author badge. General comment default remains the established named mode with an explicit anonymous option; no silent policy switch for other members. Edited comments are not introduced in L2.

Existing follow requests are reused; accept/decline/cancel/unfollow are voluntary. Pair-level transaction locks serialize follow/block operations. New non-trusted direct conversations reuse conversations/members/messages but stay PENDING until recipient accepts. Existing accepted conversations retain access. Current request settings, professional-only preference and blocks are rechecked at acceptance. Only recipient can accept/decline; sender may cancel. Decline prevents repeat sender requests to the same closed conversation, not global account lockout. No message body is available while pending. Listener service kinds/acceptance remain separate.

Notifications contain no post narrative preview. Anonymous actors are redacted at read time, including historical records; inaccessible/hidden/deleted comment/post notices and unread counts are filtered. Follow acceptance and message requests use named relationships only. Search keeps existing authorized projections/ordering and now exposes bounded result pagination with stale-response cleanup. No drafts or pending content enter ordinary search.

## Audit follow-up

FOLLOWING responses include nullable `followingAnyone`: a boolean derived only from the authenticated viewer's current active, unblocked follow relationships; null for other modes. It never identifies a followed account or changes anonymous-post exclusion. The UI distinguishes no follows, no permitted stories, loading and a failed request. Old clients can ignore the additive field; old servers omitting it retain the generic empty message rather than claiming no follows.

Comment reactions now reuse the visible-comment projection, in addition to parent-post access, so both block directions and inactive comment authors prevent direct reaction writes. A known old comment ID does not bypass the listing predicate.
