# Journal and private writing lifecycle
Existing wellbeing_journal_entries remains the journal store. Owner-only bounded history/search, exact record reads, revisioned edit and deletion extend it. Tags and mood are optional; a blank title receives a neutral title. Server timestamps and retry keys prevent client-time manipulation and duplicate creates. A stale revision returns 409 without overwriting the current row. Private writing never becomes a post, notification, learning recommendation or administrative moderation case.
Drafts are explicitly saved to an owner-only server row, expire seven days after the last saved edit, disappear from reads/exports at expiry, and are removed in bounded scheduled batches. Unprotected device/localStorage draft persistence is absent. Unsaved changes remain in memory, with navigation/removal and browser-close warnings. Logout/account changes remount private state; inactive rendering is hidden; stale async responses check the auth generation. No fully offline persistence or physical native-device verification is claimed.
Answers persist until owner deletion. User erasure explicitly removes daily sets/answers and drafts, and existing journal/mood/goals/reflections. Goal steps cascade. Full own archive includes all records, rather than only the bounded home snapshot, and includes the exact original prompt revision. Production backup retention and deletion replay remain governed by J and unverified operational requirements; no claim of erasing every backup is made.
