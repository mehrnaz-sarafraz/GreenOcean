# Private learning reward ledger

V66 adds versioned growth_reward_rules, an append-only growth_reward_ledger and private growth_learning_badges. It does not backfill arbitrary historical progress or claim old percentages are learning. Production `greenocean.education.rewards-enabled` defaults false, separately from learning/content/sensitive-processing gates. A genuine O3 LearningEvent is consumed synchronously in its existing transaction: ledger and learning completion either commit together or roll back together.

The only sources are owned current published LESSON, correctly completed optional EXERCISE, and complete COURSE events. PostgreSQL derives course/activity identity from the completion; validates active eligible ownership, current reviewed availability and rule amount; and rejects arbitrary amounts or foreign source IDs. Defaults: lesson10, exercise5, course30. Configuration `reward-rule-version`, `lesson-points`, `exercise-points`, `course-points` is bounded to0–1000. Changed values require a new positive rule version; stored versions cannot be repriced. No user can submit a balance, points or owner identity to the dashboard.

Uniqueness is owner + source type + original course key + stable lesson key (or course key for course completion). Digests/revisions change actual learning requirements in O3, but cannot farm points. An exercise can earn once for the stable lesson, irrespective of retakes or revisions. Restarting, resetting progress or repeated HTTP requests does not remove the original award tombstone. Independent-connection races serialize with a PostgreSQL owner advisory lock and unique constraints.

Corrections append a single negative event referencing the original; amount, source and rule must exactly match. Original events cannot be overwritten. Repeating correction or replaying completion cannot reissue reversed credit. An ADMIN with existing recent privileged MFA can reverse a known case with a specific reason; the operation is audited. Deleting an eligible source completion automatically appends its reversal and updates badges. Retirement or author erasure preserves legitimately earned historical points; it does not penalize a learner for later source unavailability. Account erasure deletes that learner's ledger/badges before source records and redacts operational actor references.

Audited ADMIN reconciliation processes at most200 missing eligible events per source type per request, in chronological order, excluding all prior original awards, including reversed ones. Repeat it to process the next batch. It skips retired/unavailable/old-revision sources and never reconstructs sensitive or percentage activity. It is not automatic retroactive scoring. The ledger, source completion IDs and rule versions support reproducible balance checks; balance is SUM(point_delta), never a cached user-editable total.

Private FIRST_LESSON, FIRST_COURSE and FIVE_LESSONS badges depend on genuine unreversed ledger milestones. Earned timestamps remain stable; only invalid-credit correction can mark a badge revoked. Inactivity never removes a badge. No streaks, comparison, cash, professional credential, diagnosis or listener priority are implemented. The dashboard uses current courses from owned lesson openings and actual O3 progress; private event history is paginated20/page. No reward notifications or reminders are enabled.
