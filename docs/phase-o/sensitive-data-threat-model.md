# Phase O sensitive-data threat model
O1 attacks: ID enumeration and cross-owner edits/deletes/search/export fail through owner predicates; journal search is not part of public search. Stale revisions fail with 409. Unicode/markup is displayed as native text; null bytes and excessive lengths are rejected. Bounded pages and per-account rate limits constrain input/read abuse. Auth generation and account-keyed UI prevent late responses crossing accounts; inactive screens hide private text. No private values enter application error logs, notifications, analytics, feeds, groups, listeners or reward sources.
Residual risks: unsaved memory can be lost if a process/device terminates; explicit short-lived private server drafts are available under the approved policy. Device screenshots/compromised OS and production database/backup access require operational controls. Physical background/VoiceOver/TalkBack checks and backup-erasure replay are not represented by JS exports. O2–O4 threat evidence will extend this document after each milestone.
