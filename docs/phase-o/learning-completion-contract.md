# Learning completion integrity
An eligible adult explicitly opens an available reviewed lesson. The server records only its latest owned course/lesson/revision/digest opening, not reading duration, camera/microphone, sensitive text or a browsing trail. Completion requires an explicit reading/activity acknowledgement for that exact current content and an owned opening. This is honest self-paced participation, not proof of comprehension, invigilation, clinical improvement or professional certification.
PostgreSQL guards verify current reviewed source/owner/receipt and uniqueness; a lesson completion event is server-derived and retry-idempotent. Course progress is completed required lesson digests divided by actual current required lesson digests. Course completion requires all of them and cannot be posted as an arbitrary percentage. The former percentage PATCH returns 409. Optional factual checks allow calm retakes; only a correct published option creates one eligible exercise event. No free-text private response is required, stored or rewarded.
Stable lesson keys and content digests preserve completion for unchanged material across course revisions. Changed/new required material requires a fresh explicit opening/completion; original historical events remain private. Retired/unavailable material cannot create new credit. Source-author erasure removes the source body/identity but retains the learner's own minimal deidentified completion metadata (opaque source key, lesson/course title/version/time) until that learner deletes it through account rights. Learner erasure removes their pending openings, completions and subsequent rewards. This does not claim physical deletion of every backup.
O4 consumes only these real lesson/exercise/course events; journal, mood, daily answer, social and listener activity are never eligible reward sources.
