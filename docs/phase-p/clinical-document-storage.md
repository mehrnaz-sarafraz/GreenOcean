# Private document storage
P1 credentials accept signature-checked PDF/JPEG/PNG, maximum10MiB, at most20 per application. AES-256-GCM ciphertext binds the credential application as associated data. Versioned key IDs support retaining old decryption keys during rotation. No production key is embedded; missing current key prevents storage. Files use private permissions and randomized storage names; scanner accesses decrypted bytes in memory through the ClamAV INSTREAM adapter. Missing approved scanner, error or unknown result leaves quarantine. A controlled socket fixture tests integration only and is not evidence of malware coverage.

Purpose-audited content retrieval requires owner or current authorized staff and recent strong authentication. Responses are no-store attachments with generic names. Browser exports use local Blob URLs; native exports use a dedicated temporary cache removed after explicit sharing and at startup/logout. A recipient's exported copy cannot be recalled. Real native device lifecycle/export checks remain NOT_EXECUTED. Clinical-record attachment storage is P3 scope and is not silently enabled by credential support.
# Clinical attachments (P3)

Clinical files use purpose-isolated encrypted database blobs, separate from credential storage and generic media. Uploads are bounded to2 MB and PDF/PNG/JPEG signatures; version corrections create new linked attachments. Request multipart data remains bounded in memory before encryption (`file-size-threshold=10MB`, equal to the overall credential file limit), avoiding a framework plaintext spool file. The genuine configured ClamAV adapter scans plaintext only within the controlled process/scanner boundary. Missing/unavailable scanning leaves quarantine; rejected/pending files cannot be downloaded. No public URL or original patient filename is published. Downloads require current relationship/category or independently approved exceptional access, recent authentication and an audit entry. Explicit native export uses the existing temporary-file cleanup path; actual physical-device behavior remains unverified.

Credential-domain details above remain applicable to professional evidence rather than patient records.
