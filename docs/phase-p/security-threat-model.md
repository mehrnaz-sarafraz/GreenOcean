# Phase P threats and boundaries
P1 addresses forged/self-approved/expired credentials, stale decisions, cross-application scope borrowing, plaintext credential theft, guessed document IDs, manual CLEAN bypass, scheduling races, false presence and sensitive stale UI responses. Controls include current independent role/MFA, exact revision/evidence snapshots, exact-application scope functions, AES-GCM owner binding, genuine scanner quarantine, bounded private retrieval, account-keyed foreground-cleared screens, shared scheduling locks and PostgreSQL exclusion constraints. Notifications contain no clinical narrative. Anonymous community identity and personal wellbeing are not joined into verification. Application/database operators remain trusted infrastructure; key custody, audited operational access, backup encryption and incident response require deployment evidence. P2–P5 threats require their own implementation and tests before being marked satisfied.


P4/P5: feedback version swaps, identity disclosure, raw review privilege expansion, small-sample inference, revenue ranking manipulation, profession reclassification and concurrent weekly publication are bounded by immutable cohort snapshots, independent moderation, minimum samples and exact evidence digests. Follow-up policy drift is prevented by per-revision policy binding. New clinical access cannot use legacy adult/email grace. Replacement retries and overlapping subscriptions serialize; failed replacement transactions roll back. Generic professional messaging cannot bypass bounded encounters. Independent incident review prevents a finance checkbox from assigning no-show blame; contradictory outage evidence stops that transition. Privacy requests never imply blanket erasure; independent holds/action evidence and protected backup handling remain separate.
