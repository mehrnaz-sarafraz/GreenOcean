## Actual API and database changes

Owner GET /api/v1/account/privacy; POST decisions/receipts/rights beneath that path. Actor comes exclusively from authenticated JWT, never a supplied userId. Public policy GET supports explicit locale and version history. ADMIN governance policy review/publish and rights queue/resolve retain existing recent strong authentication. Optional permissions and Privacy receipts are separate from policy_acceptances. UI grant requires displaying exact current notice; server independently validates that notice. Manual rights handling is status/case reference only, not automatic execution of every requested legal right.

V42 adds review/locale/effective metadata and three owner-scoped governance tables; no historical optional consent/receipt is fabricated. V43 replaces the immutability function prospectively to preserve review evidence and invalidate edited drafts. Applied migrations are not edited. Report-target correction reuses existing can_read_social_post; it introduces no parallel audience infrastructure. Migration tests retain V41 hashes/profile choices/old acceptance timestamps and no synthetic grants.

## Four-persona evidence

Happy: actual registration/current Terms/verification/login, decline optional analytics, record separate Privacy receipt, own archive and unchanged profile access; real PG approved-purpose grant/withdrawal and erasure. Creative: FA/RTL/narrow UI, repeated choices, notice versions, unchanged legacy migration, independent concurrent withdrawal/topic write, final I foreground regression. Confused: unavailable/unstaffed states, failed withdrawal shows no false save, lost rights response reuses key, expired grant requires current notice. Malicious: forged grants/IDs/notice, private report enumeration, cross-owner appeals/exports, self-review/revoked reviewer/older policy/rewritten evidence, denied analytics and privileged publication.
