# Peer support session duration
New N-controlled requests capture the approved thirty-minute plan. The clock starts only at actual Phase I activation. Acceptance, queue admission and booking do not start the clock or create chat. Historical I requests with no captured plan remain governed by their original presence/reconnect contract; no migration retrofits a duration.

The server enforces the authorized deadline during reads, scheduled reconciliation and every USER message insertion. Client countdowns are presentational and use observed server time with a monotonic elapsed clock. Initial chat boundaries also explain the plan to older clients. Deduplicated system notices and the current UI warn within five minutes and one minute of ending. Late workers cannot authorize late sending or manufacture a timely warning.

Either participant may end earlier. One optional additional ten minutes requires the same proposal, both explicit approvals, current authorization and genuine capacity. Silence, typing, a reminder and reconnect never extend time. See the extension contract. Interruption and safety termination retain I's precedence.

Thirty minutes is a service-capacity policy, not a clinical judgment. No emergency monitoring or continuous availability is promised. Existing public urgent resources and non-listener services remain independent.
