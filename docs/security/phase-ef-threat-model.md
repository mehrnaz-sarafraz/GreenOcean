# Phase E/F threat model and privacy review

Assets: account credentials, session authority, staff authority, private support/messages/journal/consultation data, and minimal security history. Actors include unauthenticated attackers, stolen-token holders, malicious members, compromised staff credentials, hostile browser origins and a person sharing an unattended device. Tests use synthetic accounts only. No wellbeing browsing/content is a fraud signal.

| Threat / GreenOcean impact | Existing mitigation reused and change | Evidence and residual risk |

## Drafts and privacy lifecycle

Unsent support/journal/message drafts stay in React memory only. Short background interruptions keep them hidden under OS preview protection; no unencrypted draft persistence is added. Logout, user change, deletion, invalidated session or the five-minute fallback reauthentication unmounts private state and discards drafts. The privacy cost of retaining text across users outweighs automatic draft recovery; explain this behavior before release. Exports already downloaded by an explicit user action are user-managed files; this code cannot recall them. Pending downloads reject old epochs.

## Release boundary

No production migration/deployment/cleanup is authorized by this implementation. AAL1-aligned member target and strong staff target are scoped design choices, not conformance certificates. Real mail acceptance/delivery, native OS behavior, trusted ingress, offline breached-password corpus and independent monitoring are deployment dependencies. Production staff access remains disabled even when development WebAuthn tests pass.
